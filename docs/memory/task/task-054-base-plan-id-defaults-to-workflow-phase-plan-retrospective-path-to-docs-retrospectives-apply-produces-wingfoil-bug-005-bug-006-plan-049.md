## Context

plan-049's step 3 (ruling 4: the pack half of the fix of bug-005 and bug-006, through
`kanban-delivery`), with plan-049's rulings 1 (the fix) and 6 (dl-015 C7). `base` 1.0.0's
defaults break two of its own workflows on WingFoil 0.3.0:
- **bug-005:** `plan_id`'s default `plan-{n}-{slug}` declares neither `{workflow}` nor `{phase}`,
  so `workflow start` leaves them empty in the instance's plan, which `base`'s `plan` requires,
  and the start fails (exit 1). With `{workflow}-{phase}-plan`, WingFoil's and UI's convention,
  the start fills them (reproduced: plan-049's Context).
- **bug-006:** a `produces` that names a directory is satisfied only with a trailing slash.
  `retrospective_path`'s default `docs/retrospectives` and `apply`'s `.wingfoil` never are.

The class of the release is `major` (plan-049 ruling 2); `version` and the `base@^2` cascade
belong to `prepare` (ruling 3), not to this task: `pack.yaml` keeps `version: 1.0.0` here.

## Acceptance

1. **`packs/base/pack.yaml`:** `plan_id`'s default `{workflow}-{phase}-plan`, its description
   saying that WingFoil's `workflow start` fills `workflow` and `phase` only from the tokens the
   id pattern or the path declares; `retrospective_path`'s default `docs/retrospectives/`, its
   description saying that a directory ends with `/` and a fixed file has none.
2. **`packs/base/workflows/governance-evolution.yaml`:** `apply` produces `.wingfoil/` and
   `AGENTS.md`; its `version` 1 → 2 (an integer content revision). `retrospective.yaml`, whose
   text does not change (its `produces` is the parameter), keeps `version: 1`.
3. **`packs/base/README.md`:** the generated Parameters section regenerated by `npm run index`
   (never by hand); in "Install and update", what an adopter of 1.0.0 does: a project that relied
   on a default states it (`plan_id: plan-{n}-{slug}`), a `retrospective_path` that names a
   directory gains its slash, and a project that keeps `plan-{n}-{slug}` fills a started plan's
   `workflow` and `phase` and runs `memory submit` (or adopts the new pattern for its new plans),
   with no version, date or range of 2.0.0 (the CHANGELOG and CB-3's check belong to `prepare`);
   the example prose 2.0.0 makes untrue: `core-records`' list of defaults (`plan-{n}-{slug}`),
   `release-folders`' "its own" ids (now the default) and its `docs/09_retrospectives`. The Design
   says whether the examples that restate `{workflow}-{phase}-plan` keep it.
4. **One commit** holds `pack.yaml`, the README's example prose and the compositions that set a
   directory without the slash (plan-049 step 3), so that no commit has a README disagreeing with
   its fixtures or its defaults:
   `tests/fixtures/examples/base/release-folders/example.yaml` and
   `tests/fixtures/software-exit/compositions/release-folders/example.yaml`, both
   `retrospective_path: "docs/09_retrospectives/"`.
5. **Execution Notes**, as the task delivers: on `pack-foundation-base` (Ships: `apply`'s
   evidence; the parameter table; Adoption: the known adopters on `plan-{n}-{slug}`, this
   repository and Benchmark, their repair, the new pattern for new plans); on dl-015 (C7's
   default changed by plan-049 ruling 6); on bug-005 and bug-006 ("fixed on `main` by the merge
   `<sha>`; released in 2.0.0", plan-049 step 8).
6. **Checks:** the lint, the compositions and the matrix pass (`npm run validate`, the overlay
